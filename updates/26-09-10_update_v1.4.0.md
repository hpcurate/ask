## What was done

### The pill is icons

Three names in a 310px bar is most of a phone's width spent saying what the
shapes already say. Each tab is a glyph with its `aria-label`, and the words are
kept in the markup for the switch that brings them back under the icons
(**Shape → Words in the pill**, off by default).

The queue's glyph **becomes** its count the moment there is one, rather than
carrying a badge: a badge over an icon is two things claiming the same 22px, and
of the two the number is the one worth having. An empty queue has nothing to say,
so the icon stands.

### The tab field is ROOT's alone

`tab:` is the area *inside ROOT*. Every other project is one app, so there is
nothing for the field to name, and thirteen chips of ROOT's vocabulary under a
hub request is a question with no right answer. The field is hidden as a whole —
not emptied, so there is no orphan label — and the request files under `other`,
which is what the protocol already reads a missing tab as. Quick mode skips the
question for the same reason and by the same test, so the two cannot drift.

### One filter over both lists

A search box, a project chip row and a kind chip row, read by the queue and the
sent list alike. Not one per screen: "everything about hub" is one question, and
a queue narrowed to hub beside a history showing everything is two answers to it.

- The projects offered are the ones actually **in** the list being filtered, not
  the settings list — a filter that offers a project with nothing under it can
  only ever empty the screen.
- Tapping the chip that is already on **lifts** it, so there is no filter you can
  change but not clear.
- An untyped request reads as a **change** here, the way the protocol reads it,
  so filtering for changes finds it.
- The bar lights and carries `n of m` while it is narrowing anything: a list
  hiding rows without saying so is the one thing a receipt must never do.
- The **send** button still counts the whole queue, because sending files the
  whole queue. A button that undercounted what it was about to do would be a
  trap.

### The shape of the app

Nine dials under **Shape** in settings, each either a custom property or a data
attribute on `<html>` — so a change is one write and no redraw, the same shape
the accent already had:

| Dial | What it moves |
| --- | --- |
| Spacing | `--dens` — every padding and gap |
| Corners | `--r-base` — everything here is a block, so this is the whole shape |
| Hairlines | `--bw` — 0 lets the surfaces divide things on their own |
| Request cards | outlined, filled, or a rule |
| Chips | blocks or pills |
| Request title | the mono, or the interface font |
| Small labels in capitals | `--caps` |
| Words in the pill | the names under the icons |
| Movement | every transition at once |

A **reset** on the section head puts all nine back. The reader is written to be
safe on a store that has never heard of any of them, which is exactly what an
install upgrading into 1.4 is until its first write.

### Arriving with the request already written

`?title=…&type=fix&project=root&tab=do&prio=2&notes=…` fills the write screen in.
Every field is optional; an absent `type` and `type=` are the same thing, because
"no type" is a real answer — the one the protocol reads as a change.

- A project the settings list has never heard of is **not** refused: a new repo
  is a real request, so it becomes `other` with the name typed into the field,
  which reads as the deliberate choice it is rather than silently becoming root.
- Values this build does not have — a nonsense type, a priority of 99, a tab
  that is not a tab — are dropped, and the rest still lands. The link is a
  convenience; the form is still the form.
- **It fills the form; it does not file anything.** A link that queued on its own
  would file a request every time the page was reloaded or restored, and the one
  thing this app must never do is file the same request twice.
- The query is taken **off the address** with `replaceState`, so a reload comes
  back to the form and not to the link that opened it, and a back button cannot
  re-arm it.
- Quick mode is put away for that one request — a whole request handed over at
  once is exactly what quick mode is not — and comes back when it is queued or
  cleared. That is the same rule editing a queued request already followed.

## Verification

`node smoke.mjs` in `test/` — **117 checks passed, 0 failed** (32 added).

The added checks drive the behaviour: the pill's three icons and the count that
replaces the queue's glyph, the tab field appearing for root and not for hub (and
the request filing under `other` when it does not), the filter narrowing both
lists from one setting and saying how much it hid while the send button still
counts the queue, an untyped request reading as a change, the nine shape dials
landing as properties and attributes with a rule that reads each one, a store
with none of them still reaching the defaults, and the link filling the form,
clearing itself off the address, handling an unknown project and dropping
nonsense.

One existing check was rewritten: quick mode's "carries on to the area" no longer
holds, because a project typed into the flow is not ROOT and is no longer asked.
It now asserts the new behaviour and that the request files under `other`.

**Not verified:** anything visual. jsdom has no layout, so the icons' balance in
the pill, the filter bar's weight and every one of the nine shape dials are
Hugo's call in a browser.
